Slide 3: Project Objectives

  • We automated vehicle entry, bay assignment, and exit processing so that gate operations remain consistent even during high traffic periods.
  • We integrated cashless parking payments through M-Pesa STK Push because the mall required a trusted method that most drivers already use.
  • We implemented role-based access for Admin, Staff, and Drivers to ensure each user only performs actions that match their responsibility.
  • We added activity logs and reporting features to strengthen accountability and to support management decisions with auditable evidence.
  • We focused on delivery of a reliable working system because the final objective was not only a prototype, but a usable operational solution.

Slide 4: Proposed Solution Overview

  • The solution is a web-based parking platform for Kitengela Mall so that all user groups can access the same live data from networked devices.
  • The system tracks occupancy across Basement 1 and Basement 2 in real time, which improves allocation accuracy and reduces unnecessary searching.
  • The workflow supports staff free parking and owner monthly invoicing because these groups follow different billing rules from ordinary visitors.
  • Restricted vehicles are blocked at entry to enforce policy immediately rather than relying on manual checks after admission.
  • An administrative dashboard with reporting and database tools is included so supervisors can monitor operations and validate records quickly.

Slide 5: Technology Stack

  • We used PHP 8+ with an MVC-inspired structure because it keeps controllers, models, and services organized for easier maintenance.
  • The interface is built with HTML, CSS, and JavaScript so the system runs in standard browsers without requiring special client software.
  • MySQL or MariaDB stores operational data because both engines are stable, widely supported, and suitable for transactional records.
  • Apache on XAMPP and Docker support were included to allow both local academic deployment and reproducible environment setup.
  • Safaricom Daraja STK Push was selected as the payment API because it aligns with local payment behavior and reduces cash dependence.

Slide 6: Core Modules

  • The Gate Entry module captures number plates and validates restrictions before assigning bays so that unauthorized vehicles are stopped early.
  • The Gate Exit module computes fees and verifies payment status so that a vehicle can only leave when business rules are satisfied.
  • The Driver Payment module collects phone details and triggers STK Push with live status updates, which reduces uncertainty at the exit point.
  • The Admin Panel centralizes dashboard metrics, user management, reports, and logs to support day-to-day governance and escalation handling.
  • The Public Display module publishes live bay availability to improve driver guidance and reduce internal circulation congestion.

Slide 8: Security and Control Features

  • Role-based access control separates Super Admin, Sub-Admin, Staff, and Driver permissions so that high-risk actions remain tightly governed.
  • Administrative actions are protected with account controls to reduce accidental misuse and unauthorized configuration changes.
  • Login activity, page access, and report downloads are logged because accountability depends on traceable administrator behavior.
  • Restricted vehicles are denied at gate entry so policy enforcement happens immediately and consistently in real time.
  • Data management operations retain a visible audit trail so supervisors can verify what changed, when it changed, and who initiated it.

Slide 9: Key Improvements and Reliability

  • We redesigned M-Pesa failure handling to include a retry path because drivers need guided recovery instead of abrupt error interruptions (improved user experience).
  • We reset the payment state on each new STK attempt so that retries read fresh status and do not immediately fail from stale values (reliable retries).
  • We prevented bay release on failed payment to ensure that occupancy and revenue controls remain synchronized at all times (operational safety).
  • We removed duplicate transaction creation so financial records map cleanly to confirmed callbacks and reconciliation remains accurate (data integrity).
  • We expanded admin database search and controlled table clearing because operations teams need visibility while still preserving safe boundaries.

Slide 11: Results and Impact

  • Gate operations became faster because entry and exit decisions now rely on instant digital checks instead of manual verification.
  • Visibility of available bays improved because occupancy is tracked continuously and presented in a format that staff can interpret quickly.
  • Revenue tracking and accountability improved because transaction evidence and administrator actions are now systematically auditable.
  • Administrative workflows are cleaner since reports, logs, and management actions are available from a single operational interface.
  • The architecture provides a scalable base for future smart parking features because integration points are already structured and tested.

Slide 12: Challenges and Lessons Learned

  • API integration required careful callback and error handling because network delays and user-side interruptions are unavoidable in real deployments.
  • Real-time flows demanded strict state management so that user interfaces always reflected valid and current transaction outcomes.
  • Role separation proved essential because administrative convenience must never override system security and accountability controls.
  • Failure-case testing was as important as success-case testing since production reliability depends on graceful recovery behavior.

Slide 13: Conclusion and Future Work

  • We successfully built and tested a complete parking management system that addresses entry control, payment, monitoring, and administration in one platform.
  • The project demonstrates a practical digital solution for mall parking operations because it combines operational efficiency with auditable governance.
  • Future work will include ANPR recognition, SMS receipts, analytics, and mobile integration so the system can deliver deeper automation and user convenience.
